1. Justificación Arquitectónica y Patrón MVVM (RA 1)

Para garantizar una base sólida, escalable y mantenible se ha estructurado la solución bajo el patrón de diseño Model-View-ViewModel (MVVM) apoyado en el framework Ionic 8 con React 18 y TypeScript:

  • Model (src/models/): Define de forma inmutable y con tipado estricto los contratos de datos de la plataforma (usuarios, roles ADMIN y STANDARD, tokens JWT, expedientes empresariales y estados de validación reactiva).
  • ViewModel (src/hooks/): Custom hooks (useLoginForm, useRegisterForm, useRecordForm) que encapsulan la lógica de negocio, binding bidireccional, gestión de estados de error y consumo de servicios, abstrayendo a las vistas de la manipulación de datos.
  • View (src/pages/ y src/components/): Vistas declarativas puras en JSX libres de efectos secundarios directos o lógica impura, optimizadas mediante useMemo y React.memo para evitar ciclos de renderizado innecesarios.
  • Gestión de Estado Predecible: Implementada mediante AuthContext.tsx (Context API), proveyendo control síncrono y asíncrono sobre la sesión del usuario, emisión de tokens y control de permisos RBAC.

2. Desarrollo de Requisitos — Fase 1

2.1. Paso 1.1 — Sistema de Enrutamiento y Navegación (RA 1)

  • Carga Diferida (Lazy Loading): Todas las rutas principales están desacopladas mediante React.lazy() y envueltas en <Suspense> con indicador de carga accesible (LoadingSpinner). El empaquetado de producción de Vite genera chunks independientes (ej. LoginPage-*.js, RegisterPage-*.js, DashboardPage-*.js).
  • Navegación Global (Side Menu): Diseñado con IonSplitPane y IonMenu (SideMenu.tsx). En pantallas grandes (escritorio/tablets) se presenta integrado de forma fija lateral, adaptándose en dispositivos móviles a menú flotante desplegable mediante botón hamburguesa.
  • Control de Acceso Basado en Roles (RBAC): El componente ProtectedRoute.tsx realiza una doble verificación:
    1. Autenticación: Si el usuario no ha iniciado sesión, redirige a /login manteniendo la ruta de origen en memoria para retorno posterior.
    2. Autorización por Rol: Si un usuario con rol Estándar intenta acceder a rutas reservadas para administradores (como /admin/users), el sistema intercepta la petición y redirige a la vista de error 403 (/unauthorized).
  • Manejo Seguro de Tokens: La capa de servicios genera y valida tokens simulados en formato estándar JWT (Header.Payload.Signature en Base64) con expiración temporal y persistencia local cifrada en localStorage.

2.2. Paso 1.2 — Formularios y Validaciones Asíncronas (RA 2)

  • Marcado Declarativo en JSX: Interfaces libres de manipulación directa del DOM (como getElementById), utilizando componentes modulares y el elemento reutilizable FormInput.tsx.
  • Data Binding Unidireccional y Bidireccional: Enlace controlado en dos direcciones entre el estado reactivo del ViewModel y los componentes de Ionic mediante las propiedades value y eventos onIonInput.
  • Validación Asíncrona en Tiempo Real con Debounce:
    • Alta de Usuarios (RegisterPage.tsx): Al introducir el correo corporativo, se dispara un temporizador de debounce de 500 ms que consulta al servicio asíncrono authService.checkEmailAvailability(). Muestra un estado interactivo "Comprobando disponibilidad del correo en el servidor..." con spinner. Si el correo ya existe (ej. admin@empresa.com), marca el campo como no disponible e impide el envío. Si está libre, emite confirmación positiva.
    • Alta de Expedientes (NewRecordPage.tsx): Validación asíncrona de unicidad del código de expediente corporativo (con formato regulado EXP-AAAA-NNN).
  • Accesibilidad y Normativa WAI-ARIA: Todos los campos cuentan con atributos aria-required, aria-invalid reactivo, aria-describedby dinámico enlazado al mensaje de error y regiones informativas con role="alert" y aria-live="polite".
